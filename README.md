# FeMoco Resource Estimation

Resource estimates for ground-state energy estimation of FeMoco (FeMoco-54 and FeMoco-76) on cat qubits.
The code compiles the sum-of-squares (SOS) block encoding and phase estimation into rounds, Toffolis, |i⟩-states and physical qubits.
It does this for two architectures: the repetition-cat architecture and the hybrid LDPC-cat architecture.

It produces the numbers, tables and figures of:

> *Ground-state energy estimation compiled on cat qubits: 6 808 qubits for FeMoco-54 in 23.6 hours*,
> [arXiv:2610.37840](https://arxiv.org/abs/2610.37840) (v2, 2026-11-18; v1, 2026-10-27).

## Setup

The environment is managed with [pixi](https://pixi.sh) and pinned in `pixi.lock` (macOS arm64, Linux x86-64 and Linux arm64):

```bash
pixi install
pixi run test
```

`pixi run` puts the repository root on `PYTHONPATH`, so `resource_count` imports without installing it.

## Tables and figures

The paper's tables and figures are generated by scripts and are not committed.
Regenerate them with:

| Command | Output | Time |
| --- | --- | --- |
| `pixi run tables` | 7 `.tex` files with the paper's tables, in `generated_tables/` (they use the paper's macros, e.g. `\keti`, `\CXCXX`) | seconds |
| `pixi run figures` | the λ scans (`scan_<level>.json`) and the 5 figure PDFs, in `figs/` | a few minutes per noise level |
| `pixi run replot` | the figure PDFs again, from the scans already in `figs/` | seconds |

Each `*_latex.py` script also runs on its own and prints its table to the terminal, and `lambda_scan.py <level>` prints one noise level's scan; each docstring lists the arguments.
`figure_style.py` (the figures' colours and type) is a helper module.
To get the numbers of a specific version (such as the submitted one), check out that version's tag and rerun the tasks.

The comparison with the surface-code estimate of Low et al. ([arXiv:2605.30455](https://arxiv.org/abs/2605.30455)) uses their Table XXVII, which is not included in this repository.
`scripts/lambda_scan.py` (`LOW26_MISSING`) describes how to supply it; without it, everything else runs as usual.

## Notebook

`notebooks/visualization.ipynb` explores the results interactively.
Open it in VS Code or another Jupyter front end and select the pixi environment's Python (`.pixi/envs/default`) as its kernel.
The two λ-scan cells take a few minutes each.

## Where things are

| Path | Contents |
| --- | --- |
| `resource_count/settings.py` | The molecules (N, B, R, C, bit precisions) and, per molecule and architecture, the compute-zone budget and lookup options. **Every result is computed from these, so change parameters here, if you want to explore other parameter sets.** |
| `resource_count/cost_functions.py` | Cost of each primitive in the repetition-cat model. |
| `resource_count/cost_functions_ldpc.py` | The same primitives in the hybrid LDPC-cat model, with the same interface. |
| `resource_count/high_level_cost.py` | The block encoding and phase estimation assembled from the primitives, with idle qubits charged step by step. |
| `resource_count/layout.py` | Zone sizes (system, address, Fourier state, buffer) and the budget check. |
| `resource_count/batching.py`, `optimize.py` | Lookup-table batching options for RPrep + Rot, and the search over options. |
| `resource_count/error_accounting.py` | Failure probability, distance choice and physical qubit count of a full run. |
| `resource_count/accounting.py` | The cost-record format shared by both models. |
| `resource_count/lambda_scan.py`, `cross_options.py` | The compute-zone scan and the cross-architecture comparison behind the figures and the cross-options table. |
| `scripts/` | Table and figure generators (see above). |
| `notebooks/visualization.ipynb` | Interactive exploration: results per molecule, error accounting, the trade-offs between lookup options. |
| `tests/` | Unit tests, model invariants, and regression tests that pin exact outputs. |
| `resource_count.md` | Design notes: parameters, zones, and the qubit usage of each subroutine. |

## Tests

`pixi run test` runs the unit tests, the model invariants and the regression tests.
`tests/test_regression.py` pins the exact output of a fixed set of calls, so a change to the model that moves a number fails there on purpose.
Its docstring explains how to update the pinned values once you've checked the new ones.
